# Fluxtype Velocity Engine

A professional-grade, high-fidelity typing performance auditor built for the modern web. Fluxtype is designed with a "Linguistic Purity" philosophy, prioritizing technical accuracy, atomic state management, and ergonomic UI/UX.

## Architectural Philosophy

Fluxtype is engineered using a **Stateless Service Worker** architecture (Manifest V3), ensuring total resilience to the ephemeral lifecycle of browser extensions.

### 1. Atomic Persistence (Read-Modify-Write)
All storage operations are serialized via a dedicated `AsyncQueue`. This eliminates race conditions during multi-context interactions (e.g., simultaneous updates from the Popup and Background scripts).

### 2. Categorized Messaging Bridge
Communication follows a strict **Action/Query/Event** paradigm:
- **Actions**: State-mutating requests with integrity checks.
- **Queries**: Read-only data retrieval with low-latency delivery.
- **Events**: Fire-and-forget broadcasts for decoupling domain events.

### 3. Linguistic Delivery (Infinite Flow)
The linguistic engine implements an O(n) **Fisher-Yates (Grand Shuffle)** on full word pools. It uses a circular buffer pattern to provide an uninterrupted stream of data, ensuring the main thread is never blocked by heavy dictionary processing.

### 4. Performance Telemetry
- **Burst Mitigation**: Peak WPM is calculated using a 5-key rolling average, clamped at 350 WPM to eliminate unrealistic spikes caused by keyboard repeat-rate artifacts.
- **Heatmap Analytics**: Spatial distribution of latency and error rates across the virtual keyboard matrix.

## Technical Stack
- **Core**: Vanilla JavaScript (ES6+ Modules)
- **State Management**: Chrome Storage (Local/Session) with Async Serialization
- **UI/UX**: HTML5, Vanilla CSS3 (Glassmorphism + CSS Variables)
- **Security**: Manifest V3 compliant, zero external dependencies (excluding local `html2canvas`).
